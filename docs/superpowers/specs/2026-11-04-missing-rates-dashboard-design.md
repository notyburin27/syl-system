# Dashboard ค่าขนส่ง / ค่าเที่ยวที่ยังขาด (เดือนก่อนหน้า) — Design

## ที่มาและเหตุผล

ทุกเดือนตอนปิดยอด ผู้ใช้ (ADMIN) ให้ AI กวาดข้อมูล prod ทำเป็น Excel เช่น
`งานเดือน9-2569-ไม่มีค่าเที่ยว-ค่าขนส่ง-v7.xlsx` เพื่อดูว่างานไหนยังไม่มีค่าขนส่ง (income)
หรือค่าเที่ยว (driverWage) แล้วไปหาราคามาเพิ่ม rate_income เอง (ผ่าน SQL) ทำซ้ำหลายรอบ (v1 → v7)

ต้องการหน้าในระบบแทน Excel นี้ — เห็นสิ่งที่ขาดรวมเป็นกลุ่มตาม key ของอัตรา, กดตั้งค่าอัตราได้ทันที,
และหลังบันทึกระบบ **เติมค่าให้งานในกลุ่มนั้นทันที** (ผู้ใช้ยืนยัน)

แบบอย่าง UI: หน้าช่วงน้ำมัน (`components/summary/FuelSegmentsView.tsx`) — การ์ดสรุป + Segmented filter
+ ตาราง + ปุ่ม "ตั้งค่า" ชิดขวาต่อรายการที่ขาด + "job กรอกข้อมูลไม่ครบ" เมื่อ key ไม่ครบ

## Goals

- ดูได้ **เฉพาะเดือนก่อนหน้า** เท่านั้น (คำนวณจากวันนี้ตามเวลา Asia/Bangkok — วันนี้ 2026-11-04 → 2026-10) ไม่มีตัวเลือกเดือน
- แสดงงานที่ไม่มีค่าขนส่ง / ไม่มีค่าเที่ยว รวมเป็นกลุ่มตาม key ของอัตรา
- ตั้งค่าอัตราค่าขนส่งแบบ "ช่วงเดี่ยว": ระบบแนะนำช่วงราคาน้ำมันที่ครอบคลุมทุก job ในกลุ่ม ผู้ใช้กรอกราคาต่อช่วง
- ตั้งค่าอัตราค่าเที่ยว: กรอกเลขเดียว
- บันทึกแล้วเติมค่าให้ job ในกลุ่มทันที (เฉพาะช่องที่ยัง null)
- กลุ่มที่มีอัตราตรง key แล้วแต่ job ยังว่าง (ยังไม่ได้กดดึงค่า) — แสดงแยกพร้อมปุ่ม "เติมเลย"

## Non-goals / Anti-goals

- **ไม่ทำ** ระบบแนะนำชื่อโรงงานที่พิมพ์ผิด (ผู้ใช้ตัดออก)
- ไม่ให้เลือกเดือนอื่น
- ไม่แก้ข้อมูล job ที่ไม่ครบ (ลูกค้า/โรงงาน/SIZE) จากหน้านี้ — แค่แสดงว่า "job กรอกข้อมูลไม่ครบ"
- ไม่ทับค่าที่มีอยู่แล้ว (เติมเฉพาะ null) — ห้ามทับยอดที่กรอก/ปิดไปแล้ว
- ไม่แตะการดูดซับทอยตู้ (logic นั้นอยู่ใน `/api/jobs/prefill-rates`)
- ไม่แก้ `/api/jobs/prefill-rates` และหน้าตั้งค่าอัตราเดิม

## กฎการนับ (ต้องตรงกับ Excel และ prefill-rates)

job ในเดือนก่อนหน้า (`jobDate` ในช่วง `[YYYY-MM-01, เดือนถัดไป)`) ที่:
- `isCancelled = false`
- `jobType` ไม่ใช่ `advance`, `noJob`
- ไม่ใช่ใบรองของงานจับคู่ (`pairLinkAsSecondary = null`) — ยอดต้อง null เสมอ
- **ค่าเที่ยว**: ไม่นับทอยตู้ที่ถูกดูดซับ (`isTowingAbsorbed = true`) — ค่าเที่ยวต้อง null เสมอ
  และไม่นับทอยตู้ที่ **จะถูกดูดซับ** เมื่อกด prefill (ยังไม่ได้กด) — ตัดสินด้วย `isAbsorbPickupName` + `isAbsorbedBy`
  จาก `lib/utils/towingAbsorb.ts` แบบเดียวกับขั้นดูดซับของ prefill (อ่านอย่างเดียว ไม่ตั้ง flag) ; fill ก็ข้ามใบเหล่านี้
  (ส่วนตัดสินใจของ Claude หลัง builder check — กันผู้ใช้ตั้งอัตรา/เติมค่าเที่ยวให้ทอยที่ไม่ควรมี)
- **ค่าขนส่ง**: ไม่นับ `towing` (ทอยตู้ปกติไม่มีค่าขนส่ง) — `towingHeavy` ยังนับ

size ที่ใช้หาอัตรา: ใบหลักของงานจับคู่ (`pairLinkAsPrimary != null`) ใช้ `getPairedSize(size) ?? size` (เช่น 20DC → 2x20DC) — เหมือน prefill-rates

### ค่าขนส่ง (income null)
- key: `jobType + rateSize + factoryLocationId + customerId` (= unique ของ `RateIncome`)
- key ไม่ครบ (ขาดลูกค้า/โรงงาน/size) → กลุ่ม "ข้อมูลไม่ครบ" (ระบุว่าขาดอะไร)
- มี `RateIncome` ตรง key → สถานะ "มีอัตราแล้ว ยังไม่เติม"
- ไม่มี → "ไม่มีอัตรา"

### ค่าเที่ยว (driverWage null)
- key: `jobType + rateSize + factoryLocationId` (`factoryLocationId` เป็น null ได้ — เหมือน prefill: `${jobType}|${size}|${factoryLocationId ?? ""}`)
- ต้องมีโรงงาน ยกเว้นตระกูลทอยตู้ (`isTowingJobType`) ; ไม่มี size หรือ (ไม่ใช่ทอยและไม่มีโรงงาน) → "ข้อมูลไม่ครบ"
- มี `RateDriverWage` ตรง key → "มีอัตราแล้ว ยังไม่เติม" ; ไม่มี → "ไม่มีอัตรา"

## หน้าจอ

ตำแหน่ง: เมนูตั้งค่า กลุ่ม "อัตรา" หน้าใหม่ **"ค่าที่ยังขาด"** `/jobs/settings/rates/missing`
(ส่วนตัดสินใจของ Claude หลัง builder check: สิทธิ์ **ADMIN เท่านั้น** — ตรงกับ `/api/jobs/prefill-rates`
เพราะหน้านี้เติมค่าให้งานที่เคลียร์แล้วได้ ซึ่ง `PATCH /api/jobs/[id]` ล็อคไว้ และวันนี้มีแค่ ADMIN ที่ทำผ่าน prefill ได้)

```
ค่าที่ยังขาด · ตุลาคม 2569                                    [รีเฟรช]
[ไม่มีค่าขนส่ง: N งาน] [ไม่มีค่าเที่ยว: N งาน] [มีอัตราแล้ว ยังไม่เติม: N งาน] [ข้อมูลไม่ครบ: N งาน]

Segmented: ค่าขนส่ง (กลุ่ม) | ค่าเที่ยว (กลุ่ม)
Segmented ย่อย: ทั้งหมด | ไม่มีอัตรา | มีอัตราแล้ว | ข้อมูลไม่ครบ

ตารางค่าขนส่ง: ลูกค้า | โรงงาน | ลักษณะงาน | SIZE | จำนวน job (ลิงก์→modal รายการงาน) | ราคาน้ำมัน (ต่ำสุด–สูงสุด) | สถานะ | [action]
ตารางค่าเที่ยว: โรงงาน | ลักษณะงาน | SIZE | จำนวน job | สถานะ | [action]
action: ไม่มีอัตรา → [ตั้งค่า] ; มีอัตราแล้ว → [เติมเลย] ; ข้อมูลไม่ครบ → ข้อความสีเหลือง "job กรอกข้อมูลไม่ครบ (ไม่มี โรงงาน/ลูกค้า/SIZE)"
```

- Modal รายการงาน: เลขงาน, วันที่, คนขับ, เบอร์รถ, ราคาน้ำมัน ณ วันงาน
- ตัวเลขการ์ดนับเป็น **จำนวน job** ; label ใน Segmented ใส่จำนวนกลุ่ม
- ไม่มีอะไรขาด → Empty "งานเดือนนี้มีค่าครบแล้ว"

### Modal ตั้งค่าค่าขนส่ง
- หัว: ลูกค้า · โรงงาน · ลักษณะงาน · SIZE · N งาน
- ตารางช่วงที่แนะนำ: `ราคาน้ำมัน min – max` (อ่านอย่างเดียว) | จำนวน job ในช่วง | ราคา (InputNumber, required)
- บันทึก → สร้าง `RateIncome` + surcharge แล้วเติม job ในกลุ่ม → message `บันทึกและเติมค่าขนส่ง N งาน` → refetch

### Modal ตั้งค่าค่าเที่ยว
- หัว: โรงงาน (หรือ "—" สำหรับทอย) · ลักษณะงาน · SIZE · N งาน ; InputNumber ค่าเที่ยว
- บันทึก → สร้าง `RateDriverWage` แล้วเติม → refetch

### ปุ่ม "เติมเลย"
- เติม job ในกลุ่มด้วยอัตราที่มีอยู่ → message `เติมค่า N งาน` → refetch

## การแนะนำช่วงราคาน้ำมัน (ค่าขนส่ง)

- ราคาน้ำมันของ job = `FuelPriceLog` ล่าสุดที่ `effectiveDate <= jobDate`
- ช่วงตั้งต้น: ขั้นละ 2 บาท ขอบ `.01` ที่เลขคู่ — `[2k+0.01, 2k+2.01)` เช่น 41.44 → 40.01–42.01, 43.54 → 42.01–44.01
  (รูปแบบที่ใช้มากที่สุดใน prod: 121 + 58 + 38 จาก 448 อัตรา)
- ถ้าลูกค้ารายนี้มีอัตราอื่นที่มี surcharge อยู่แล้ว → ใช้ช่วงของอัตรานั้นที่ครอบราคาน้ำมันของ job แทน
  (เลือกอัตราของลูกค้ารายนี้ที่ jobType เดียวกันก่อน ถ้าไม่มีใช้อัตราใดก็ได้ของลูกค้า — ล่าสุด `updatedAt`)
  ถ้าราคาน้ำมันตกนอกทุกช่วงของตารางนั้น ใช้ช่วง 2 บาทตั้งต้นสำหรับราคานั้น
- ได้ชุดช่วงที่ไม่ซ้ำกัน เรียงจากน้อยไปมาก — ทุก job ในกลุ่มตกอยู่ในช่วงใดช่วงหนึ่ง
- job ที่ไม่มีราคาน้ำมัน (ไม่มี log ก่อนวันงาน) → แสดงคำเตือนใน modal และให้กรอกราคาฐาน 1 ช่อง "ไม่มีราคาน้ำมัน" (เก็บเป็น income ฐาน)

## การบันทึก RateIncome จากช่วงเดี่ยว (ส่วนตัดสินใจของ Claude)

- `income` (ราคาฐาน) = ราคาต่ำสุดที่กรอก (ถ้ามีช่อง "ไม่มีราคาน้ำมัน" ใช้ช่องนั้นเป็นฐาน)
- สร้าง `RateIncomeFuelSurcharge` ต่อช่วง: `fuelPriceMin/Max` ตามช่วง, `surcharge = ราคาช่วง - income`
- ผล: job ที่ราคาน้ำมันอยู่ในช่วง → ได้ราคาที่กรอกพอดี ; อนาคตถ้าน้ำมันนอกช่วง → ได้ราคาฐาน (ผู้ใช้ไปเติมตารางเต็มทีหลังที่หน้าค่าขนส่งได้)
- key ซ้ำ (มีอัตราอยู่แล้ว) → 409 `มีข้อมูลนี้อยู่แล้ว`

## การเติมค่า (fill)

- เฉพาะ job ของเดือนก่อนหน้าที่ตรงกลุ่ม (key เดียวกัน, ผ่านกฎการนับ) และช่องนั้นยัง null
- income = `rate.income + surcharge ของช่วงที่ครอบราคาน้ำมัน ณ วันงาน` (สูตรเดียวกับ prefill-rates)
- driverWage = `rate.driverWage`
- เติม job ที่ `clearStatus = true` ได้ (เหมือน prefill — เติมเฉพาะ null ไม่ทับยอดที่ปิดไปแล้ว)
- สร้างอัตรา + เติม ทำใน transaction เดียว

## API (ใหม่ทั้งหมด, `requireApiRoles(ADMIN_ROLES)`)

- `GET /api/rates/missing` → `{ month, income: { groups, ... }, driverWage: { groups, ... } }`
- `POST /api/rates/missing/income` body `{ jobType, size, factoryLocationId, customerId, ranges: [{ fuelPriceMin, fuelPriceMax, price }], basePrice? }` → สร้างอัตรา + เติม → `{ filled }`
- `POST /api/rates/missing/driver-wage` body `{ jobType, size, factoryLocationId | null, driverWage }` → `{ filled }`
- `POST /api/rates/missing/fill` body `{ kind: 'income' | 'driverWage', key... }` → เติมจากอัตราที่มี → `{ filled }`
- เดือนเป้าหมายคำนวณฝั่ง server เสมอ (client ส่งเดือนไม่ได้)

## ข้อจำกัด

- Next.js 15 App Router, antd v5, Prisma v6 — ตาม CLAUDE.md (`<Table size="small">`, `App.useApp().message`, data-testid ตามกติกา)
- logic จัดกลุ่ม/แนะนำช่วง/คำนวณ income เป็น pure function ใน `lib/utils/` พร้อม unit test (`node:test` ผ่าน `npm run test:unit`)
- ไม่มีการเปลี่ยน schema

## ปล่อยให้ builder ตัดสินใจ

- โครงไฟล์ / ชื่อ component / รูปแบบ response ละเอียด
- จัดวางสี tag สถานะ (แนะนำ: ไม่มีอัตรา = orange, มีอัตราแล้ว = blue, ข้อมูลไม่ครบ = gold)
- E2E ครอบ flow หลัก: ตั้งค่าค่าขนส่งจากกลุ่ม → งานได้ค่า, ตั้งค่าค่าเที่ยว, เติมเลย
