# สรุปงานคนขับรายเดือน (Driver Monthly Summary)

วันที่: 2026-09-13

## ภาพรวม

เพิ่มเมนู **"สรุปงาน"** (เห็นเฉพาะ ADMIN) สำหรับดูสรุปรายได้/ค่าใช้จ่ายของคนขับแต่ละคนเป็นรายเดือน
และ export เป็น Excel ที่มีหน้าตาเหมือนไฟล์ที่ทีมใช้อยู่เดิม (`สรุปกลุ่ม1 เดือน 7.xlsx`)

พร้อมเพิ่ม 2 field ใน "จัดการคนขับรถ" ที่สรุปงานต้องใช้ และแก้ bug ค้นหาคนขับในหน้า job

งานแบ่งเป็น 3 ส่วนอิสระ:

1. เพิ่ม `baseSalary` + `startDate` ใน Driver
2. เมนูสรุปงาน (หน้า list + หน้ารายคน + Excel export)
3. แก้ bug ค้นหาคนขับข้าม tab ในหน้า job

## ส่วนที่ 1 — เพิ่ม field ในจัดการคนขับรถ

### Schema

```prisma
model Driver {
  // ...ของเดิม
  baseSalary  Decimal?  @db.Decimal(10, 2)   // ฐานเงินเดือน — ADMIN เท่านั้น
  startDate   DateTime? @db.Date             // วันเริ่มงาน
}
```

ทั้งคู่ nullable — คนขับที่มีอยู่แล้วไม่ต้อง migrate ข้อมูล

### `baseSalary` — ข้อมูลลับ เห็นเฉพาะ ADMIN

**สำคัญ: ต้องกรองที่ API ไม่ใช่แค่ซ่อนใน UI** เพราะ MANAGER เข้าหน้าจัดการคนขับได้
ถ้าซ่อนแค่ฝั่ง client แล้ว API ยังส่งค่ามา MANAGER เปิด devtools หรือยิง `/api/drivers` ตรงๆ ก็เห็นเงินเดือนทุกคน

- `GET /api/drivers` — ถ้า `session.user.role !== 'ADMIN'` ให้ลบ field `baseSalary` ออกจากทุก record ก่อนส่ง response
- `POST /api/drivers` และ `PATCH /api/drivers/[id]` — ถ้าไม่ใช่ ADMIN ให้ **ไม่รับ** ค่า `baseSalary` จาก body (ไม่ต้อง error แค่เพิกเฉย) ป้องกัน MANAGER แก้เงินเดือนผ่าน API

ฝั่ง UI (`DriverManager.tsx`):
- รับ prop `isAdmin` (ตอนนี้ยังไม่ได้รับ — `app/(protected)/jobs/settings/drivers/page.tsx` ต้องส่งเข้ามา อ่าน role จาก `auth()` แบบเดียวกับ `app/(protected)/jobs/page.tsx`)
- คอลัมน์ "ฐานเงินเดือน" ในตาราง — render เฉพาะเมื่อ `isAdmin`
- `Form.Item name="baseSalary"` ในโมดัลเพิ่ม/แก้ไข — render เฉพาะเมื่อ `isAdmin` ใช้ `InputNumber`

### `startDate` — วันเริ่มงาน ทุก role เห็นได้

ไม่ใช่ข้อมูลลับ ไม่ต้องกรองที่ API

- คอลัมน์ "วันเริ่มงาน" ในตาราง แสดง `DD/MM/YYYY` (พ.ศ.) หรือ `-` ถ้าว่าง
- `Form.Item name="startDate"` ใช้ `<DatePicker id="driver-start-date">` ในโมดัล
- ค่านี้ไปแสดงบนหัว Excel เป็น `เริ่มขับรับรถ 25/8/68` (D/M/YY พ.ศ.) — ถ้าว่างให้เว้นบรรทัดนั้นว่าง

### types/job.ts

```ts
export interface Driver {
  // ...
  baseSalary: number | null;   // undefined เมื่อ API กรองออก (non-admin)
  startDate: string | null;
}
```

## ส่วนที่ 2 — เมนูสรุปงาน

### สิทธิ์

เห็นและเข้าได้**เฉพาะ ADMIN** ต้องกันทั้ง 3 ชั้น:

1. เมนูใน `ProtectedLayoutClient.tsx` — ใส่ใน `isAdmin` branch เท่านั้น
2. `app/(protected)/summary/page.tsx` และ `[driverId]/page.tsx` — เช็ค `auth()` แล้ว `redirect('/jobs')` ถ้าไม่ใช่ ADMIN
3. `app/api/summary/**` ทุก route — return 403 ถ้าไม่ใช่ ADMIN

### หน้า list — `/summary`

**เลือกเดือน**: `<DatePicker picker="month">` แบบเดียวกับหน้า job (`DriverJobList.tsx`)
default = เดือนปัจจุบัน, จำ state ผ่าน query param `?month=YYYY-MM` เพื่อให้กดกลับจากหน้ารายคนแล้วยังอยู่เดือนเดิม

**การแสดงผล**: default แสดงคนขับ**ทุกคนทุกกลุ่ม** จัดเป็นหัวข้อตามกลุ่ม (`กลุ่ม 1`, `กลุ่ม 2`, …)
คนที่ไม่ระบุกลุ่มรวมอยู่ใต้หัวข้อ `กลุ่มอื่นๆ` ท้ายสุด — เรียงต่อกันลงมาในหน้าเดียว **ไม่มี pagination**

ต่างจากหน้า job ที่ใช้ Tabs (เห็นทีละกลุ่ม) เพราะหน้าสรุปต้องการเห็นภาพรวมทั้งหมดทีเดียว

**Filter กลุ่ม**: `<Select id="summary-group-filter" mode="multiple">` เลือกได้หลายกลุ่ม
ว่างไว้ = เห็นทุกกลุ่ม

**ค้นหา**: `<Input>` inline ค้นจาก **ชื่อคนขับ หรือ เบอร์รถ** (case-insensitive, substring)
กรองการ์ดที่แสดงอยู่ — ไม่ต้องใช้ modal เพราะหน้านี้ไม่มี tab จึงไม่มีปัญหาข้าม tab

**การ์ดคนขับ**: แสดงชื่อ, เบอร์รถ, **ชื่อกลุ่ม**, และตัวเลขสรุปย่อ
คลิกแล้วไป `/summary/[driverId]?month=YYYY-MM`

**ปุ่ม download**: export คนขับตาม filter ที่เลือกอยู่ เป็นไฟล์เดียวแยก sheet ตามคน
- เลือก `กลุ่ม 1` → `สรุปกลุ่ม1 เดือน 7.xlsx`
- เลือกหลายกลุ่ม → `สรุปกลุ่ม1,กลุ่ม3 เดือน 7.xlsx`
- ไม่เลือกกลุ่ม → `สรุปทุกกลุ่ม เดือน 7.xlsx` เรียง sheet ตามกลุ่ม
- เปิด modal ให้เลือก **ช่วงเดือน** ก่อน download (ดูหัวข้อ "การเลือกช่วงเดือน")

### หน้ารายคน — `/summary/[driverId]`

แสดงบล็อกสรุปตามรูปแบบเดียวกับ Excel (ลาหยุด/ซ่อมรถ/งาน/ทอย/แบก/ค้างคืน/รายได้/…)
ช่องที่ระบบไม่มีข้อมูลให้แสดงเป็นค่าว่าง

มีปุ่ม download รายคน (เลือกช่วงเดือนได้เหมือนกัน) ได้ไฟล์ 1 sheet

### การเลือกช่วงเดือน

ทั้งสองหน้าใช้ modal เดียวกัน: `<DatePicker.RangePicker picker="month">`
default = เดือนที่กำลังดูอยู่ (ช่วงเดือนเดียว)

ใน Excel แต่ละเดือนเป็นบล็อกเรียงจากซ้ายไปขวา โดย**เดือนล่าสุดอยู่ซ้ายสุด** (ตามไฟล์ต้นฉบับ: B–E = ก.ค. เดือนล่าสุด, I–L = มิ.ย. เดือนก่อนหน้า)

## การคำนวณตัวเลข

### ค่าที่ระบบคำนวณให้ได้

| แถวใน Excel | ที่มา |
|---|---|
| ลาหยุด (วัน) | นับ `DriverLeave` ของคนขับในเดือนนั้น |
| ซ่อมรถ (วัน) | นับ job ที่ `jobType='noJob'` และ `noJobReason='repair'` |
| งาน (เที่ยว) | นับ job ที่ `jobType` ∈ `inbound`/`outbound`/`flatbed`/`mill` |
| ทอย (เที่ยว) | นับ job ที่ `jobType='towing'` |
| รายได้ (บาท) | `SUM(job.income)` ของทุก job ในเดือน |
| ราคาน้ำมันต่อลิตร | **ค่าเฉลี่ย** ของ `FuelPriceLog` ทุก record ที่ `effectiveDate` อยู่ในเดือนนั้น (ดูหมายเหตุ) |
| จำนวนน้ำมัน (ลิตร) | `SUM(fuelOfficeLiters + fuelCashLiters + fuelCreditLiters)` — สูตรเดียวกับที่ `jobsExcelGenerator.ts:409` ใช้อยู่ |
| ค่าเที่ยว (บาท) | `SUM(job.driverWage)` |
| เงินเดือน (บาท) | `driver.baseSalary` จากส่วนที่ 1 |

ทุก job ที่ `isCancelled = true` **ไม่นับ** ในทุกการคำนวณ

**หมายเหตุ "ราคาน้ำมันต่อลิตร"** (แก้ไข 2026-09-13 หลังตรวจกับข้อมูลจริง):
ตอนแรก spec กำหนดให้ใช้ราคา *ล่าสุด* ของเดือน ซึ่ง**ผิด** — ตรวจกับ production แล้วพบว่าแต่ละเดือนมีราคาหลายค่า
(ก.ค. 2026 มี 4 ค่า: 37.50 / 34.94 / 35.79 / 36.69 · มิ.ย. 2026 มี 11 ค่า: 37.50–41.50)
แต่ไฟล์ Excel ต้นฉบับใช้ค่าเดียวทั้งเดือนเท่ากันทุกคน (ก.ค.=36, มิ.ย.=39) ซึ่งราคาล่าสุดให้ 36.69 กับ 37.50 — ไม่ตรงทั้งคู่

ผู้ใช้ยืนยันว่าให้ใช้ **ค่าเฉลี่ยทั้งเดือน** ซึ่งตรวจแล้วตรง: เฉลี่ย ก.ค. = 36.23 (Excel 36), เฉลี่ย มิ.ย. = 39.25 (Excel 39)
— ตัวเลขใน Excel ต้นฉบับถูกปัดเศษด้วยมือ ระบบจึงเก็บค่าเฉลี่ยจริงไม่ปัด เพื่อไม่ให้เสียความแม่นยำตอนคูณเป็น `รวมใช้น้ำมัน`

ถ้าเดือนไหนไม่มี `FuelPriceLog` เลย ค่านี้เป็น `null` (เว้นว่างใน Excel) ไม่ใช่ 0

**หมายเหตุ "ซ่อมรถ"**: เดิมเข้าใจว่าไม่มีในระบบ แต่ตรวจแล้วพบว่ามีอยู่ในรูป
`jobType='noJob'` + `noJobReason='repair'` (ดู `NO_JOB_REASONS` ใน `types/job.ts`) จึงคำนวณอัตโนมัติได้
ไม่ต้องกรอกมือ

### ช่องที่เว้นว่างให้กรอกใน Excel เอง

ระบบยังไม่มีข้อมูลเหล่านี้ และ**ไม่เก็บลง DB** — ปล่อยเป็น cell ว่างใน Excel ที่มีสูตรรออยู่แล้ว
ผู้ใช้กรอกในไฟล์ Excel เองหลัง download:

- แบก (เที่ยว)
- ค้างคืน (วัน)
- หัก น้ำมัน/หยุด (บาท)
- ค่าใช้จ่ายต่างๆ (บาท)
- สรุปให้เงินเดือนคนรถ (บาท)

เมื่อกรอกแล้ว สูตรในแถวอื่นจะคำนวณต่อให้เอง (เช่น กรอก "หัก น้ำมัน/หยุด" แล้วแถว "รวม" อัปเดตทันที)

## Excel Generator

สร้าง `lib/utils/summaryExcelGenerator.ts` ใช้ `exceljs` (มีใน dependency แล้ว)
generator ตัวเดียวรองรับทั้งสองหน้า — หน้ารายคน = 1 sheet, หน้า list = N sheets วนตามคนขับ

### โครงสร้าง sheet

- ชื่อ sheet = `ชื่อคนขับ + เบอร์รถ` เช่น `ประวิทย์ 113`, `มานัส566`
  (ต้อง sanitize: ตัดอักขระที่ Excel ห้าม `[]:*?/\` และจำกัด 31 ตัวอักษร)
- แต่ละเดือน = บล็อก 6 คอลัมน์ เดือนล่าสุดซ้ายสุด
  - บล็อกที่ 1: B, C, D, E (+ F, G เป็นตัวคั่น)
  - บล็อกที่ 2: I, J, K, L
  - บล็อกที่ n: offset 6 คอลัมน์ต่อบล็อก

### ผัง cell ภายใน 1 บล็อก (อ้างอิงบล็อกแรก B–E)

| แถว | คอลัมน์ B (label) | คอลัมน์ D (ค่า) | คอลัมน์ E (หน่วย) |
|---|---|---|---|
| 2 | `เงินเดือน: <เดือนไทย> <ปี พ.ศ. 2 หลัก>` | `(<วันจ่าย>)` — ดูหมายเหตุ | `<ชื่อกลุ่ม>` — พื้นส้ม |
| 3 | `<เบอร์รถ>` | `<ชื่อคนขับ>` (merge D3:E3) | |
| 4 | | `เริ่มขับรับรถ <startDate>` (merge D4:E4) | |
| 5 | `ลาหยุด` — แดง | จำนวน | `วัน` — แดง |
| 6 | `ซ่อมรถ` | จำนวน | `วัน` |
| 7 | `งาน` — เขียว | จำนวน — เขียว | `เที่ยว` — เขียว |
| 8 | `ทอย` — เขียว | จำนวน — เขียว | `เที่ยว` — เขียว |
| 9 | `แบก` — เขียว | *(ว่าง)* | `เที่ยว` — เขียว |
| 10 | `ค้างคืน` | *(ว่าง)* | `วัน` |
| 12 | `รายได้` | ตัวเลข | `บาท` |
| 13 | `55%` (fmt `0%`, ค่า 0.55) | `=D12*55%` | `บาท` |
| 14 | `45%` (fmt `0%`, ค่า 0.45) | `=D12*45%` | `บาท` |
| 16 | `ราคาน้ำมันต่อลิตร` | ตัวเลข | `บาท` |
| 17 | `จำนวนน้ำมัน` | ตัวเลข | `ลิตร` |

| 26 | `รวม` | `=D22+D23+D24` | `บาท` |
| 28 | `สรุปให้เงินเดือนคนรถ` | *(ว่าง)* | `บาท` — พื้นเขียว `FF92D050` |
| 30 | `ค่าใช้จ่ายต่างๆ` — แดง | *(ว่าง)* | `บาท` — แดง |
| 32 | `ยอดคงเหลือของบริษัท` | `=D12-D18-D28-D30` | `บาท` — พื้นเหลือง `FFFFFF00` |

แถว 11, 15, 19, 21, 25, 27, 29, 31 เว้นว่างเป็นตัวคั่น

**หมายเหตุ "วันจ่าย" (D2)**: ในไฟล์ต้นฉบับ เดือน ก.ค. 69 แสดง `(15/8/69)` และ มิ.ย. 69 แสดง `(15/7/69)`
คือ **วันที่ 15 ของเดือนถัดจากเดือนที่สรุป** (จ่ายเงินเดือนเดือน ก.ค. ในวันที่ 15 ส.ค.)
รูปแบบ `D/M/YY` ปี พ.ศ. 2 หลัก — generator คำนวณเองจากเดือนที่สรุป ไม่ต้องกรอก

**หมายเหตุ "เดือนไทย"**: ไฟล์ต้นฉบับสะกด `กรกฏาคม` (ฏ ปฏัก) ซึ่งต่างจากการสะกดมาตรฐาน `กรกฎาคม` (ฎ ชฎา)
ให้ใช้การสะกดมาตรฐาน — ไม่กระทบการคำนวณใดๆ เป็นแค่ข้อความหัวบล็อก

หมายเหตุ: แถว 28 "สรุปให้เงินเดือนคนรถ" **ไม่ใส่สูตร** เว้นว่างให้กรอกเอง (ตามไฟล์ต้นฉบับที่เป็นค่าคงที่)
แต่แถว 32 อ้างถึง D28 อยู่ ดังนั้นพอกรอก D28 แล้ว D32 จะคำนวณให้เอง

### Styling (ตรงกับไฟล์ต้นฉบับ)

- Font: **Courier New 16 bold** ทุก cell
- สี: แดง `FFFF0000` (ลาหยุด, หักน้ำมัน, ค่าใช้จ่าย) · เขียว `FF00B050` (งาน/ทอย/แบก)
- พื้น: ส้ม `FFFFC000` (กลุ่ม) · เขียว `FF92D050` (สรุปเงินเดือน) · เหลือง `FFFFFF00` (ยอดคงเหลือ) · ชมพูอ่อน (45%-น้ำมัน)
- Number format: `#,##0.00` สำหรับจำนวนเงิน, `0%` สำหรับ B13/B14
- Alignment: label ชิดขวา, หน่วยชิดซ้าย, หัวบล็อก center
- ความสูงแถว 24, ความกว้างคอลัมน์: B=35.5, C=2.5, D=21.5, E=10.83, F=3, G=10.83, H=2.83
- เส้นขอบรอบบล็อกตามต้นฉบับ

### API

`GET /api/summary?month=YYYY-MM` — คืน array ของสรุปคนขับทุกคน (สำหรับหน้า list)
`GET /api/summary/[driverId]?month=YYYY-MM` — สรุปคนเดียว
`GET /api/summary/export?from=YYYY-MM&to=YYYY-MM&groups=...&driverId=...` — คืนไฟล์ Excel
- ถ้ามี `driverId` → 1 sheet
- ถ้าไม่มี → ทุกคนตาม `groups` (ว่าง = ทุกกลุ่ม)

กติกาคนขับที่ลาออก: ใช้แบบเดียวกับ `/api/jobs/summary` — ลาออกเดือนไหนยังเห็นในเดือนนั้น

## ส่วนที่ 3 — แก้ bug ค้นหาคนขับหน้า job

### อาการ

ในหน้า `/jobs` พิมพ์ชื่อคนขับที่อยู่คนละ tab (คนละกลุ่ม) แล้วหาไม่เจอ

### สาเหตุ

`components/jobs/DriverJobList.tsx:197-204` — กรองกลุ่มก่อน แล้วค่อยกรองคำค้น:

```ts
const byGroup = summaries.filter((s) =>
  activeGroup === OTHER_GROUP_KEY ? !s.groupName : s.groupName === activeGroup
)
if (!searchText.trim()) return byGroup
return byGroup.filter((s) => s.driverName.toLowerCase().includes(...))
```

คนขับที่อยู่คนละกลุ่มถูกตัดทิ้งตั้งแต่บรรทัดแรก ไม่ว่าคำค้นจะตรงแค่ไหน

### วิธีแก้

เปลี่ยนช่องค้นหา inline เป็น **ปุ่ม + modal** (คงพฤติกรรม Tabs ของหน้า job ไว้):

- สร้าง `components/jobs/DriverSearchModal.tsx` ใหม่ (แยกจาก `JobSearchModal` ที่มีอยู่ — คนละเรื่อง อันนั้นค้นเลข JOB)
- ปุ่ม "ค้นหาคนขับ" วางข้างปุ่ม "ค้นหา JOB" แทนช่อง `Input` เดิม
- modal ค้นจาก `summaries` **ทั้งชุด ไม่ผ่านตัวกรองกลุ่ม** — แก้ bug ที่ต้นเหตุ
- ค้นได้ทั้ง **ชื่อคนขับ และ เบอร์รถ**
- ผลลัพธ์แต่ละรายการแสดงชื่อ + เบอร์รถ + **ชื่อกลุ่ม** (ให้รู้ว่าอยู่กลุ่มไหน)
- คลิกผลลัพธ์ → ปิด modal, `setActiveGroup(กลุ่มของคนนั้น)`, scroll ไปที่การ์ดคนนั้น

ลบ state `searchText` และ logic กรองคำค้นออกจาก `filteredSummaries` (เหลือแค่กรองกลุ่ม)
